@ create_agent | 7
D: The LangChain 1.0 function for building a tool-calling agent loop, configurable with middleware.
U: You need a production agent with tools, a system prompt and pluggable behaviour hooks.
T: create_agent replaces langgraph.prebuilt.create_react_agent as the recommended agent API.
F: create_agent is imported from langchain_community.agents.
C: from langchain.agents import create_agent\nagent = create_agent(model="openai:gpt-5.5", tools=[search], system_prompt="Be helpful.")
B: from langchain.agents import ____\nagent = ____(model="openai:gpt-5.5", tools=[search]) ;; create_agent ;; AgentExecutor ;; initialize_agent ;; create_react_agent

@ Middleware | 7
D: Pluggable hooks that intercept the agent loop before/after model calls, around tool calls, and at start/end.
U: You want to redact emails, summarize long histories and require human approval without rewriting the agent loop.
T: Middleware is passed to create_agent through the middleware= list.
F: Middleware can only run after the agent has finished.
C: agent = create_agent(model, tools, middleware=[SummarizationMiddleware(...), HumanInTheLoopMiddleware(...)])

@ before_model hook | 7
D: Middleware hook that runs before each model call, e.g. to trim or inspect messages.
T: before_model runs before every model call in the agent loop, not just once.
F: before_model runs only once when the agent finishes.
C: @before_model\ndef trim(state, runtime): ...

@ wrap_model_call hook | 7
D: Middleware hook that wraps each model call, able to modify the request, retry, or swap the model.
U: Long conversations should be routed to a larger model automatically.
T: A wrap_model_call middleware receives the request and a handler to call the model.
F: wrap_model_call can only read the response and cannot change the request.
C: @wrap_model_call\ndef pick(request, handler):\n    return handler(request.override(model=big_model))

@ wrap_tool_call hook | 7
D: Middleware hook that wraps each tool execution, useful for retries, logging or blocking calls.
T: wrap_tool_call runs around tool executions rather than model calls.
F: wrap_tool_call runs before the agent starts and never again.
C: @wrap_tool_call\ndef log_tools(request, handler):\n    return handler(request)

@ SummarizationMiddleware | 7
D: Built-in middleware that summarizes older messages when a token or message threshold is reached.
U: Chat histories grow beyond the context window during long support sessions.
T: SummarizationMiddleware can trigger on token count and keep the most recent messages.
F: SummarizationMiddleware deletes the whole conversation when triggered.
C: SummarizationMiddleware(model="openai:gpt-5.4-mini", trigger=("tokens", 4000), keep=("messages", 20))

@ HumanInTheLoopMiddleware | 7
D: Built-in middleware that pauses before selected tool calls so a human can approve, edit or reject them.
U: The agent must not send emails without a person approving first.
T: HumanInTheLoopMiddleware requires a checkpointer so the run can pause and resume.
F: HumanInTheLoopMiddleware works without any persistence layer.
C: HumanInTheLoopMiddleware(interrupt_on={"send_email": True})

@ PIIMiddleware | 7
D: Built-in middleware that detects and redacts, masks or blocks personal data such as emails.
T: PIIMiddleware can redact emails from user input before the model sees them.
F: PIIMiddleware encrypts the entire conversation with a user key.
C: PIIMiddleware("email", strategy="redact", apply_to_input=True)

@ ModelCallLimitMiddleware | 7
D: Built-in middleware that caps the number of model calls in a run or thread.
U: You must stop runaway agents from looping and burning tokens.
T: ModelCallLimitMiddleware(run_limit=10) stops a run after ten model calls.
F: ModelCallLimitMiddleware limits the number of tools you can register.
C: ModelCallLimitMiddleware(run_limit=10)

@ dynamic_prompt | 7
D: Decorator for middleware that computes the system prompt at runtime from state or context.
T: A @dynamic_prompt function returns the system prompt string to use for the call.
F: dynamic_prompt changes the tools list instead of the prompt.
C: @dynamic_prompt\ndef by_role(request):\n    return f"You assist a {request.runtime.context['role']}."

@ response_format | 5
D: create_agent argument that makes the agent return a validated structured object in structured_response.
T: create_agent(..., response_format=Ticket) puts the result in result["structured_response"].
F: response_format changes the HTTP content type of the agent server.
C: agent = create_agent(model, tools, response_format=Ticket)\nresult["structured_response"]

@ AIMessage | 2
D: The message type returned by chat models, carrying content, tool_calls and usage metadata.
T: AIMessage.usage_metadata reports input and output token counts when the provider returns them.
F: Chat models return plain strings, not message objects.
C: reply = model.invoke("hi")\nreply.content, reply.tool_calls, reply.usage_metadata

@ content_blocks | 2
D: Standardized, provider-agnostic view of message content such as text, reasoning, images and tool calls.
T: content_blocks normalizes content across providers in LangChain v1.
F: content_blocks only work with OpenAI responses.
C: for block in reply.content_blocks:\n    print(block["type"])

@ ToolMessage | 2
D: Message type that carries a tool's result back to the model, linked by tool_call_id.
T: A ToolMessage must reference the id of the tool call it answers.
F: ToolMessage is used to send the system prompt.
C: ToolMessage(content="22 degrees", tool_call_id=ai.tool_calls[0]["id"])

@ SystemMessage | 2
D: Message type holding instructions that set the model's behaviour for the conversation.
T: A SystemMessage is typically placed first in the message list.
F: SystemMessage contains the model's own reply.
C: [SystemMessage("You are concise."), HumanMessage("What is RAG?")]

@ stream() | 2
D: Runnable method that yields output chunks as they are generated.
U: Tokens should appear progressively in a chat UI.
T: model.stream(...) yields AIMessageChunk objects.
F: stream() returns only after the full response is complete.
C: for chunk in model.stream("Write a haiku"):\n    print(chunk.content, end="")

@ batch() | 2
D: Runnable method that runs many inputs, in parallel where possible, returning outputs in input order.
T: runnable.batch([a, b]) returns a list of outputs in the same order as the inputs.
F: batch() processes inputs strictly one at a time and returns them shuffled.
C: model.batch(["Q1", "Q2", "Q3"])

@ with_fallbacks | 2
D: Runnable method that tries alternative runnables when the primary one raises an error.
U: If OpenAI times out, the chain should automatically try Anthropic.
T: with_fallbacks only uses the fallback when the primary runnable raises an exception.
F: with_fallbacks calls every fallback in parallel and merges the answers.
C: robust = model.with_fallbacks([init_chat_model("anthropic:claude-sonnet-5")])

@ with_retry | 2
D: Runnable method that automatically retries a failing call a configured number of times.
T: with_retry(stop_after_attempt=3) retries up to three attempts.
F: with_retry caches the first successful output forever.
C: model.with_retry(stop_after_attempt=3)

@ InMemoryRateLimiter | 2
D: A rate limiter you attach to chat models to cap requests per second.
T: A rate_limiter can be passed when constructing a chat model.
F: InMemoryRateLimiter limits tokens per prompt instead of request rate.
C: limiter = InMemoryRateLimiter(requests_per_second=2)\nmodel = init_chat_model("openai:gpt-5.5", rate_limiter=limiter)

@ LCEL | 4
D: The LangChain Expression Language, which composes runnables with the | operator into chains.
T: In prompt | model | parser, the output of each step becomes the input of the next.
F: LCEL chains run from right to left.
C: chain = prompt | model | StrOutputParser()

@ Runnable | 4
D: The common interface (invoke, batch, stream and async variants) implemented by prompts, models, parsers and retrievers.
T: Retrievers implement the Runnable interface, so they can be piped in LCEL.
F: Only chat models implement the Runnable interface.
C: retriever.invoke("query")\nprompt.invoke({"q": "hi"})

@ RunnableLambda | 4
D: Wraps a plain Python function so it can be used as a runnable in a chain.
T: (RunnableLambda(lambda x: x + 1) | RunnableLambda(lambda x: x * 2)).invoke(3) returns 8.
F: RunnableLambda can only wrap async functions.
C: add_one = RunnableLambda(lambda x: x + 1)

@ RunnableParallel | 4
D: Runs several runnables on the same input concurrently and returns a dict of their outputs.
U: You need both retrieved context and the original question passed to the prompt.
T: RunnableParallel(a=r1, b=r2).invoke(x) returns {"a": ..., "b": ...}.
F: RunnableParallel runs branches sequentially and returns only the last output.
C: RunnableParallel(context=retriever | format_docs, question=RunnablePassthrough())

@ RunnablePassthrough | 4
D: Runnable that returns its input unchanged, often used to forward the question in a RAG chain.
T: RunnablePassthrough().invoke("x") returns "x".
F: RunnablePassthrough calls the LLM with its input.
C: {"context": retriever | format_docs, "question": RunnablePassthrough()}

@ RunnablePassthrough.assign | 4
D: Keeps all input keys and adds new keys computed from the input.
T: RunnablePassthrough.assign(n=lambda d: len(d["text"])) on {"text": "abc"} returns {"text": "abc", "n": 3}.
F: assign() removes the original keys and keeps only the new ones.
C: RunnablePassthrough.assign(n=lambda d: len(d["text"]))

> Order of steps in a basic RAG pipeline with LangChain | 8 | load documents ; split into chunks ; embed and store in a vector store ; retrieve relevant chunks ; generate the answer with the LLM
> What happens when a chat model requests a tool | 6 | model returns an AIMessage with tool_calls ; your code runs the tool with the given args ; a ToolMessage with the result is appended ; the model is called again to produce the answer
> Data flow through an LCEL chain of prompt, model and StrOutputParser | 4 | input dict fills the prompt template ; prompt value is sent to the chat model ; the model returns an AIMessage ; the parser returns the message text as a string
