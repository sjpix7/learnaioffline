# LLM Models. Lessons: 1 transformer, 2 tokens, 3 training, 4 decoding, 5 context/KV cache, 6 landscape, 7 reasoning/MoE, 8 quantization/serving, 9 prompting/fine-tuning
@ Transformer | 1
D: The neural architecture based on self-attention, introduced in "Attention Is All You Need" (2017), behind modern LLMs.
T: Most modern LLMs are decoder-only Transformers.
F: Transformers process text strictly one character at a time with recurrence.
C: # Vaswani et al., 2017

@ Self-attention | 1
D: The mechanism letting each token mix information from other tokens weighted by learned relevance.
T: Attention weights are computed from queries and keys and applied to values.
F: Self-attention ignores the other tokens in the sequence.
C: Attention(Q, K, V) = softmax(Q @ K.T / sqrt(d_k)) @ V

@ Scaling by sqrt(d_k) | 1
D: Dividing attention logits by the square root of the key dimension to keep softmax inputs well-scaled.
T: Scaling prevents attention logits from growing too large.
F: The scaling factor is the vocabulary size.
C: scores = Q @ K.T / math.sqrt(d_k)

@ Causal mask | 1
D: A mask preventing each position from attending to future tokens in decoder models.
T: The causal mask enables next-token prediction training.
F: The causal mask lets tokens attend to future tokens.
C: mask = torch.triu(torch.ones(n, n), diagonal=1).bool()

@ Multi-head attention | 1
D: Running several attention heads in parallel so the model can learn different relationships.
T: Each head has its own query, key and value projections.
F: Multi-head attention uses a single shared attention pattern.
C: # h heads, each of size d_model / h

@ RoPE | 1
D: Rotary positional embeddings that encode position by rotating query and key vectors.
T: RoPE is used by many modern LLMs such as Llama and Qwen.
F: RoPE is a tokenization algorithm.
C: # rotate q, k by angle θ·position

@ Quadratic attention cost | 1
D: Standard attention computes n² scores for a sequence of n tokens.
T: Doubling sequence length roughly quadruples the attention score matrix.
F: Attention cost grows linearly with sequence length.
C: # n = 8,000 tokens -> 64 million attention scores per head per layer

@ Grouped-Query Attention | 1
D: Sharing each key/value head among several query heads to shrink the KV cache.
T: GQA reduces KV cache memory compared with full multi-head attention.
F: GQA increases the number of KV heads.
C: # 32 query heads, 8 KV heads

@ FlashAttention | 1
D: An exact attention algorithm that reduces memory reads/writes for faster training and inference.
T: FlashAttention computes exact attention, not an approximation.
F: FlashAttention approximates attention with random features.
C: # fused, tiled attention kernel

@ Encoder-only model | 1
D: Transformer like BERT that reads the whole input bidirectionally, used for classification and embeddings.
T: BERT is an encoder-only model.
F: BERT is a decoder-only chat model.
C: AutoModel.from_pretrained("bert-base-uncased")

@ Encoder-decoder model | 1
D: Transformer like T5 or BART with an encoder for input and a decoder for output, common for translation.
T: T5 is an encoder-decoder model.
F: T5 is an encoder-only model.
C: AutoModelForSeq2SeqLM.from_pretrained("t5-small")

@ Token | 2
D: A sub-word unit from a fixed vocabulary that models read and generate.
T: In English, one token is roughly four characters on average.
F: One token always equals one word.
C: enc.encode("Tokenization matters!")

@ Byte-Pair Encoding | 2
D: A tokenization algorithm that repeatedly merges the most frequent adjacent symbol pair into a new token.
T: GPT models use byte-level BPE tokenizers.
F: BPE splits text only at spaces.
C: tiktoken.get_encoding("o200k_base")

@ WordPiece | 2
D: The sub-word tokenization algorithm used by BERT.
T: BERT uses WordPiece tokenization.
F: WordPiece is used by all GPT models.
C: # "playing" -> ["play", "##ing"]

@ SentencePiece / Unigram | 2
D: Tokenization approaches that work on raw text (including spaces) and are popular for multilingual models like T5 and Gemma.
T: SentencePiece treats the input as a raw character stream.
F: SentencePiece requires text to be pre-split into words.
C: # "▁Hello" marks a leading space

@ Token pricing | 2
D: API billing per token, usually with different prices for input, output and cached input.
T: Output tokens usually cost more than input tokens.
F: APIs charge per request regardless of length.
C: cost = inp/1e6 * in_price + out/1e6 * out_price

@ Words-to-tokens rule of thumb | 2
D: In English, about 0.75 words per token (100 tokens ≈ 75 words).
T: 1,000 English words are roughly 1,300 tokens.
F: 1,000 English words are roughly 250 tokens.
C: tokens ≈ words / 0.75

@ Tokenization artifacts | 2
D: Errors caused by how text is split into tokens, such as miscounting letters or mishandling long numbers.
T: Counting letters in a word can be hard because the model sees tokens, not characters.
F: Tokenization never affects model behaviour.
C: # "strawberry" may be split into tokens like "str", "aw", "berry"

@ Pre-training | 3
D: Self-supervised next-token prediction on trillions of tokens, producing a base model.
T: A base model continues text but may not follow instructions reliably.
F: Pre-training uses only human-labelled instruction data.
C: loss = cross_entropy(logits[:, :-1], tokens[:, 1:])

@ Scaling laws | 3
D: Empirical relationships between loss and model size, data and compute.
T: Chinchilla suggested about 20 training tokens per parameter for compute-optimal training.
F: Scaling laws show that data size has no effect on loss.
C: # Kaplan 2020; Hoffmann (Chinchilla) 2022

@ Supervised fine-tuning | 3
D: Training on curated instruction–response pairs so the model follows instructions and a chat format.
T: SFT turns a base model into an instruction-following model.
F: SFT requires a reward model and RL.
C: SFTTrainer(model=model, train_dataset=chats).train()

@ RLHF | 3
D: Reinforcement learning from human feedback: train a reward model on preferences, then optimize the policy (e.g. PPO) with a KL penalty.
T: RLHF uses a reward model trained on human preference comparisons.
F: RLHF trains without any human preference data.
C: # preferences -> reward model -> PPO with KL to SFT model

@ DPO | 3
D: Direct Preference Optimization: training directly on chosen vs rejected pairs without a separate reward model or RL loop.
T: DPO removes the need for a separate reward model.
F: DPO requires PPO rollouts.
C: DPOTrainer(model=model, ref_model=ref, train_dataset=pairs).train()

@ Constitutional AI | 3
D: Anthropic's approach using AI feedback guided by written principles to align models.
T: Constitutional AI uses a set of principles to guide AI feedback.
F: Constitutional AI forbids any training.
C: # critique and revise responses according to principles

@ GRPO | 3
D: Group Relative Policy Optimization: RL that compares a group of sampled answers instead of using a value model, popularized by DeepSeek-R1.
T: GRPO computes advantages relative to other samples in the group.
F: GRPO requires a separate critic value network.
C: GRPOTrainer(model=model, reward_funcs=[correctness]).train()

@ RL with verifiable rewards | 3
D: Training reasoning with rewards that can be checked automatically, like math answers or unit tests.
T: Verifiable rewards are used to train reasoning models.
F: Verifiable rewards require humans to score every sample.
C: reward = 1.0 if answer == ground_truth else 0.0

@ Distillation | 3
D: Training a smaller student model to imitate a larger teacher model's outputs.
T: Distillation transfers capability from big models to small ones.
F: Distillation makes the student model larger than the teacher.
C: # student learns from teacher responses / logits

@ Logits | 4
D: The raw, unnormalized scores the model outputs for every vocabulary token before softmax.
T: Softmax converts logits into probabilities.
F: Logits are already probabilities that sum to 1.
C: probs = softmax(logits / temperature)

@ Temperature | 4
D: A decoding parameter dividing logits before softmax; low values sharpen and high values flatten the distribution.
U: Your extraction pipeline gives different answers each run.
T: Lower temperature makes outputs more deterministic and focused.
F: Higher temperature makes outputs more deterministic.
C: model.invoke(prompt, temperature=0)

@ Top-k sampling | 4
D: Sampling only from the k most likely tokens.
T: top_k=1 is equivalent to greedy decoding.
F: top_k=1 samples uniformly from the whole vocabulary.
C: generate(..., top_k=40)

@ Top-p (nucleus) sampling | 4
D: Sampling from the smallest set of tokens whose cumulative probability reaches p.
T: With probabilities 0.5, 0.25, 0.15, 0.1 and top_p=0.8, the nucleus has three tokens.
F: Top-p always keeps exactly p tokens.
C: generate(..., top_p=0.9)

@ Min-p sampling | 4
D: Keeping tokens whose probability is at least min_p times the top token's probability.
T: Min-p adapts the cutoff to how confident the model is.
F: Min-p keeps only the least likely tokens.
C: generate(..., min_p=0.05)

@ Greedy decoding | 4
D: Always choosing the single most probable next token.
T: Greedy decoding is deterministic for a fixed model and input.
F: Greedy decoding samples randomly from all tokens.
C: next_token = int(np.argmax(logits))

@ Beam search | 4
D: Keeping several candidate sequences at each step and choosing the highest-scoring one.
T: Beam search is common in translation but rare in chat models.
F: Beam search is the default for chat assistants.
C: generate(..., num_beams=4)

@ Stop sequences | 4
D: Strings that end generation when produced.
T: A stop sequence can end output at a delimiter like "\n\n".
F: Stop sequences make the model generate longer outputs.
C: model.bind(stop=["\n\nQuestion:"])

@ Frequency and presence penalties | 4
D: Decoding penalties that discourage repeating tokens already generated.
T: Presence penalties encourage introducing new topics.
F: Penalties increase repetition.
C: client.chat.completions.create(..., frequency_penalty=0.5)

@ Logprobs | 4
D: Log-probabilities of generated tokens returned by some APIs, useful for confidence estimates.
T: Logprobs can serve as a rough confidence signal for classification.
F: Logprobs are the token prices.
C: client.chat.completions.create(..., logprobs=True, top_logprobs=5)

@ Context window | 5
D: The maximum number of tokens (input plus output) a model can attend to at once.
T: Frontier models in 2026 commonly offer around one-million-token windows.
F: The context window counts only output tokens.
C: # prompt_tokens + max_output_tokens <= context_window

@ Prefill | 5
D: Processing all input tokens in parallel before generation begins; determines time to first token.
T: Longer prompts increase time to first token.
F: Prefill generates the output tokens one at a time.
C: # TTFT grows with prompt length

@ Decode phase | 5
D: Generating output tokens one at a time, each requiring a forward pass.
T: Output length strongly affects total latency.
F: All output tokens are produced in one parallel step.
C: # tokens/second during decode

@ KV cache | 5
D: Stored keys and values of past tokens for each layer so they are not recomputed during decoding.
T: KV cache size grows linearly with the number of tokens.
F: The KV cache stores the model's weights.
C: kv_bytes_per_token = 2 * layers * kv_heads * head_dim * bytes

@ Time to first token | 5
D: Latency from sending a request until the first output token arrives.
T: Streaming makes perceived latency closer to time to first token.
F: Time to first token includes generating the whole answer.
C: # measure TTFT and tokens/s separately

@ Prompt caching | 5
D: Provider-side reuse of the computed state for a repeated prompt prefix, billed at a discount.
U: Every request shares the same 20,000-token system prompt and documents.
T: Putting stable content first maximizes prompt cache hits.
F: Prompt caching works best when the variable part comes first.
C: # [stable system prompt + docs] + [user question]

@ Continuous batching | 5
D: Server technique that adds and removes requests from a running batch at every step to maximize GPU utilization.
T: vLLM uses continuous batching.
F: Continuous batching waits for all requests to finish before starting new ones.
C: vllm serve Qwen/Qwen3-8B

@ PagedAttention | 5
D: vLLM's technique managing the KV cache in pages to avoid memory fragmentation.
T: PagedAttention improves memory efficiency for many concurrent requests.
F: PagedAttention is a tokenization method.
C: # KV cache blocks allocated like virtual memory pages

@ Speculative decoding | 5
D: A small draft model proposes several tokens that the large model verifies in parallel.
T: Speculative decoding can speed up generation without changing outputs.
F: Speculative decoding always reduces output quality.
C: # draft k tokens -> verify in one big-model pass

@ Needle in a haystack | 5
D: A test that hides a fact in a long context and checks whether the model retrieves it.
T: Long-context benchmarks probe whether models use all positions reliably.
F: Needle in a haystack measures training speed.
C: # insert "The secret code is 4417" at depth 50%

@ Open weights | 6
D: Model parameters that can be downloaded and run yourself, which is not always the same as fully open source.
T: An open-weights model may still have training data and code that are not public.
F: Open weights always means the training data is public.
C: ollama pull qwen3:8b

@ Llama | 6

@ Qwen | 6

@ DeepSeek-R1 | 6

F: DeepSeek-R1 is a closed model available only to one company.

@ Gemma | 6

@ Mistral AI | 6

@ Claude | 6

@ GPT | 6

@ gpt-oss | 6

@ Model router | 6
D: A component that sends easy requests to a cheap model and hard ones to a stronger model.
U: 80% of support questions are simple and you want to cut cost without hurting hard cases.
T: Routing can reduce cost while keeping quality on hard requests.
F: A model router always uses the most expensive model.
C: model = small if classify(q) == "easy" else frontier

@ LMArena | 6
D: A crowdsourced leaderboard ranking chat models by pairwise human preference votes.
T: LMArena rankings are based on human pairwise preferences.

@ Reasoning model | 7
D: A model that generates a long internal chain of thought before answering, trading test-time compute for accuracy.
U: You need better accuracy on hard math and multi-step planning problems.
T: Thinking tokens are usually billed as output tokens.
F: Reasoning models always answer faster than standard models.
C: client.responses.create(model="...", reasoning={"effort": "high"}, input=q)

@ Reasoning effort | 7
D: A control (low/medium/high or a thinking budget) for how much a reasoning model thinks.
T: Higher reasoning effort usually increases latency and cost.
F: Reasoning effort controls the vocabulary size.
C: reasoning={"effort": "low"}

@ Test-time compute | 7
D: Spending more computation at inference (longer reasoning, sampling, search) to improve answers.
T: Self-consistency is a form of test-time compute scaling.
F: Test-time compute changes the model's training data.
C: answers = [llm(q) for _ in range(8)]\nmajority_vote(answers)

@ Mixture of Experts | 7
D: Layers with many expert feed-forward networks where a router sends each token to the top-k experts.
T: In MoE models, total parameters far exceed active parameters per token.
F: In MoE models, every expert processes every token.
C: # router picks 2 of 8 experts per token

@ Active parameters | 7
D: The parameters actually used to process one token in an MoE model.
T: Mixtral 8x7B has about 47B total but about 13B active parameters per token.
F: Active parameters are always equal to total parameters in MoE.
C: # DeepSeek-V3: 671B total, ~37B active

@ MoE memory requirement | 7
D: All experts must be stored in memory even though only a few are used per token.
T: MoE saves compute per token but not weight memory.
F: MoE models only need memory for the active experts.
C: # memory ≈ total params × bytes per param

@ Multimodal LLM | 7
D: A model that accepts several input types such as text, images, audio or video.
T: Vision-language models can read charts and screenshots.
F: Multimodal LLMs only accept text.
C: HumanMessage(content=[{"type": "text", "text": "Describe"}, {"type": "image", "url": url}])

@ Weight memory formula | 8
D: Memory for weights ≈ parameters × bytes per parameter (FP16 = 2, INT8 = 1, 4-bit = 0.5).
T: A 7B model in FP16 needs about 14 GB for weights.
F: A 7B model in FP16 needs about 7 GB for weights.
C: gb = params_billion * bytes_per_param

@ Quantization | 8
D: Storing weights (and sometimes activations) in fewer bits to reduce memory and speed up inference.
U: You want to run an 8B model on a laptop GPU with 8 GB of memory.
T: 4-bit quantization reduces weight memory to about a quarter of FP16.
F: Quantization always improves model quality.
C: ollama run qwen3:8b   # 4-bit quantized by default

@ GGUF | 8
D: The llama.cpp model file format supporting quantization types like Q4_K_M and Q8_0.
T: GGUF files are used by llama.cpp and Ollama.
F: GGUF is a GPU-only format for vLLM.
C: ./llama-cli -m qwen3-8b-Q4_K_M.gguf -p "Hello"

@ GPTQ | 8
D: A post-training, layer-wise weight quantization method for GPU inference.
T: GPTQ quantizes weights after training.
F: GPTQ requires retraining the model from scratch.
C: # TheBloke/...-GPTQ

@ AWQ | 8
D: Activation-aware Weight Quantization that protects the most salient weights.
T: AWQ uses activation statistics to decide which weights matter most.
F: AWQ ignores activations entirely.
C: # model-AWQ checkpoints for vLLM

@ NF4 | 8
D: A 4-bit NormalFloat data type from bitsandbytes used by QLoRA.
T: QLoRA fine-tunes on top of a 4-bit NF4 base model.
F: NF4 is a 16-bit float format.
C: BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4")

@ Ollama | 8

@ vLLM | 8

@ llama.cpp | 8

@ SGLang | 8

@ Fine-tuning vs RAG | 9
D: Fine-tuning changes behaviour, style and format; RAG supplies fresh or private facts at query time.

@ LoRA | 9
D: Low-Rank Adaptation: freezing base weights and training a low-rank update ΔW = B·A.
U: You need to adapt a 7B model on a single GPU with little memory.
T: LoRA trains far fewer parameters than full fine-tuning.
F: LoRA updates every weight of the base model.
C: LoraConfig(r=16, lora_alpha=32, target_modules=["q_proj", "v_proj"])
B: config = LoraConfig(____=16, lora_alpha=32, target_modules=["q_proj", "v_proj"]) ;; r ;; rank_size ;; alpha ;; layers

@ QLoRA | 9
D: LoRA fine-tuning on top of a 4-bit quantized base model to fit large models on one GPU.

@ TRL | 9

@ LoRA parameter count | 9
D: Adapting a d×k matrix with rank r trains r×(d+k) parameters.

F: LoRA always trains exactly d×k parameters.
C: params = r * (d + k)

> Typical LLM training pipeline | 3 | pre-train on next-token prediction ; supervised fine-tune on instructions ; align with preference optimization (RLHF or DPO) ; RL with verifiable rewards for reasoning
> What happens when you call a chat model | 5 | the prompt is tokenized ; prefill processes all input tokens ; decode generates tokens one at a time using the KV cache ; tokens are detokenized and streamed back
> Inside one decoding step | 4 | model outputs logits ; logits are divided by the temperature ; top-k/top-p truncate the distribution ; a token is sampled from the remaining probabilities
